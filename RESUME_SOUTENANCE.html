1. Architecture générale

Le système gère la création et configuration de blocks et items Minecraft Bedrock Edition. Architecture simplifiée :

  • 3 entités : Blocks, Items, Mobs (même système)
  • Authentification : Login/Register + roles (Admin pour édition)
  • Base de données : SQLite avec tables blocks, items, mobs
  • Frontend : Blade templates + Tailwind CSS

Modèle de données (Block)

Colonne Type Description
name string Nom affiché (ex: "Mon Block")
identifier string ID unique (ex: "mon_block")
solid boolean Le bloc est-il solide (collision) ?
destructible boolean Peut-on le miner ?
resistance float (0-100) Dureté du bloc
light_emission int (0-15) Luminosité émise
geometry string Forme détectée (cube, net, glass, cross)

3. 🚨 Détection géométrie automatique

C'est le cœur du système de création. L'app analyse la texture fournie et détecte automatiquement la forme du bloc :

Condition Géométrie Interprétation Usage
Ratio 4:3 exact (64×48, 32×24)
OU cross pattern détecté		 net Texture dépliée (croix) 6 faces différentes
Transparence continue > 5%
(alpha canal graduel)		 glass Semi-transparent Verre, glaçons
Transparence binaire > 20%
(pixels transparent/opaque)		 cross Plante, herbe 2 plans croisés
Sinon (opaque entièrement) cube Bloc solide normal Pierre, brique, etc.

Détail de la détection

Net texture (4:3) :

  • Ratio exact détecté : if ($w % 4 === 0 && $h % 3 === 0 && ($w/4) === ($h/3))
  • Format standard Minecraft unfold (croix dépliée)
  • Sera traitée comme 6 faces différentes

Transparence :

  • Scanne chaque pixel du PNG
  • Compte transparent (alpha > 10) et partiellement transparent (5 < alpha < 122)
  • Glass si continu > 5%, Cross si binaire > 20%
❌ PIÈGE #1 : Ratio 4:3 strict
La détection cherche un ratio 4:3 exact. Exemples valides : 64×48, 128×96, 32×24.
Pas de 3:2, pas de carré, pas d'approximation. Si ta texture est 65×49, ce sera traité comme cube, pas net.
❌ PIÈGE #2 : Géométrie détectée ≠ réalité visuelle
La détection automatique se base uniquement sur l'analyse pixel. Si tu uploades une image opaque mais veux un cross → tu dois fournir un JSON géométrie personnalisé.

4. Comportement du block (logique)

Une fois créé, le système génère les propriétés comportementales du bloc basées sur les inputs :

Propriétés générées

{
  "identifier": "custom:{identifier}",
  "properties": {
    "solid": {input},
    "destructible": {input},
    "resistance": {input},
    "light_emission": {input},
    "geometry": {détecté},
    "hardness": {calculé = resistance / 20}
  }
}

Interprétation Minecraft

Propriété Valeur Effet
solid: true boolean Bloc a une collision (joueur ne peut pas passer)
solid: false boolean Pas de collision (pas de hitbox)
destructible: true boolean Joueur peut le miner avec outil
resistance: 25 0-100 Explosion resistance (plus élevé = plus dur à casser)
hardness: 1.25 résistance ÷ 20 Temps de mine (formule Minecraft)
light_emission: 8 0-15 Bloc émet de la lumière (comme glowstone)
❌ PIÈGE #3 : Hardness = Resistance ÷ 20
C'est une formule fixe. L'input utilisateur "resistance" (0-100) est converti en "hardness" pour Minecraft.
Exemple : resistance=40 → hardness=2.0 (le bloc se mine 2x plus vite qu'en mode normal)
❌ PIÈGE #4 : Identifier doit avoir "custom:" prefix
Dans Minecraft, les identifiants sont namespacés. Les built-ins utilisent minecraft:stone.
Tes customs blocks DOIVENT utiliser custom:{identifier}. Sans le prefix "custom:", Minecraft ignorera silencieusement le bloc.

Géométrie et rendu

Selon la géométrie détectée, le bloc a un comportement de rendu différent :

Géométrie Render method Textures Propriétés spéciales
cube opaque 1 (appliquée x6) Normal
net opaque 6 différentes (top, bottom, left, right, front, back) 6 faces uniques
glass blend 1 (semi-transparent) Dégradé alpha
cross alpha_test 1 (avec transparence binaire) Pas de face dimming

5. Gestion des textures

Traitement selon géométrie

Après détection, la texture est stockée et traitée différemment selon la forme :

Géométrie Input utilisateur Stockage Résultat
net 1 PNG (4:3) 1 fichier permanent Split en 6 PNG (top, bottom, left, right, front, back)
cube / glass / cross 1 PNG (carré) 1 fichier permanent 1 PNG inchangée, appliquée x6 faces

Net texture splitting

Quand la texture est détectée comme net, elle suit ce pattern :

Input (64×48):
   [top]
[L][F][R][B]
  [bottom]

Calcul:
  C = width / 4 = 64 / 4 = 16

Chaque région = 16×16:
  top    @ (16, 0)
  left   @ (0, 16)
  front  @ (16, 16)
  right  @ (32, 16)
  back   @ (48, 16)
  bottom @ (16, 32)
❌ PIÈGE #5 : Net texture splitting
Si tu fournis une texture 4:3, l'app la découpe automatiquement en 6 régions carrées.
Chaque région devient une face du cube. Si ta découpe n'est pas parfaite (ex: contours mal alignés), le résultat visuel sera cassé.
❌ PIÈGE #6 : Texture carrée ≠ Texture net
Une texture 64×64 (carré) ne sera JAMAIS détectée comme net, même si elle ressemble à une croix. Pourquoi ? Parce que 64÷4 ≠ 64÷3 (pas de ratio 4:3).
Pour net, tu DOIS un ratio 4:3 strict : 64×48, 80×60, 128×96, etc.

Géométrie custom (optionnel)

L'utilisateur peut uploader un fichier JSON de géométrie personnalisée au lieu de l'auto-détection :

  • Format : .json (Minecraft geometry format v1.12.0+)
  • Stockage : storage/app/geometry/{identifier}_{timestamp}.json
  • Optionnel : si absent, la géométrie détectée est utilisée

6. Validation des inputs

Règles strictes (BlockRequest)

Champ Règle Raison
name 1-50 chars, /^[a-zA-Z0-9 ]+$/ Éviter injection, caractères spéciaux
identifier /^[a-z0-9_]+$/ Standard Minecraft (minuscule + underscore)
texture PNG, carré, max 512 KB Éviter malveillance, format compatible
solid in:0,1 (booléan) Valeur stricte
destructible in:0,1 (booléan) Valeur stricte
resistance numeric, 0-100 Plage Minecraft acceptable
light_emission int 0-15 Standard Minecraft (niveau de lumière)
⚠️ Sécurité
Tous les inputs passent par validation Laravel (Eloquent + rules). Pas de SQL injection, pas de XXE, pas de path traversal.
❌ PIÈGE #7 : Texture DOIT carré
La validation ratio=1 signifie : width = height.
Une texture 64×48 sera REJETÉE (ce n'est pas carré, c'est 4:3). Pour 4:3, tu dois utiliser la détection net (pas la validation carré).
❌ PIÈGE #8 : Identifier minuscule + underscore ONLY
/^[a-z0-9_]+$/ signifie :
  • ✅ mon_block, mon_block_2
  • ❌ Mon_Block (majuscules non autorisées)
  • ❌ mon-block (tirets non autorisés)
  • ❌ mon block (espaces non autorisés)

7. Création d'items

Le système gère aussi la création d'items Minecraft (outils, armes, ressources, etc.). Contrairement aux blocks, les items n'ont pas de géométrie — ce sont des objets plats dans l'inventaire.

Modèle de données (Item)

Colonne Type Description
name string Nom affiché (ex: "Épée Magique")
identifier string (unique) ID unique (ex: "epee_magique")
texture_path string Chemin stockage permanent (item_textures/)
max_stack_size int (1-64) Nombre max d'items empilables (null = pas limité)
max_durability int Durabilité (null = indestructible)
item_tier int (0-10) Niveau de tool (vitesse de minage)
item_multiplier float Multiplicateur de vitesse d'outil
damage int (0-100) Dégâts infligés (pour armes)
hand_equipped boolean L'item est-il équippable en main ?
creator_identifier string Qui a créé l'item

Propriétés d'item Minecraft

Une fois créé, l'item génère un JSON avec ces composants :

Propriété Condition Effet
minecraft:max_stack_size Si max_stack_size fourni Nombre max empilable (1-64)
minecraft:durability Si max_durability fourni Item se casse après N utilisations
minecraft:axe Si tier ET multiplier Tool : vitesse de minage selon tier
minecraft:damage Si damage > 0 Arme : dégâts infligés en combat
minecraft:hand_equipped Si hand_equipped = true Item visible quand équippé en main
minecraft:display_name Toujours Nom affiché dans inventaire

Texture d'item

Contrairement aux blocks :

  • Pas de détection géométrie — l'item est toujours une image carrée simple
  • Une seule texture — pas de split en faces
  • Stockage : storage/app/item_textures/{identifier}_{timestamp}.png
  • Format : PNG carré (pas de ratio 4:3)
📦 Item behavior JSON (exemple)
{
  "minecraft:item": {
    "description": {
      "identifier": "custom:epee_magique",
      "category": "equipment"
    },
    "components": {
      "minecraft:display_name": { "value": "epee_magique" },
      "minecraft:damage": { "damage": 8 },
      "minecraft:durability": { "max_durability": 256 },
      "minecraft:hand_equipped": { "enabled": true }
    }
  }
}

Différences blocks vs items

Aspect Blocks Items
Géométrie Auto-détectée (net, cube, glass, cross) Aucune (image carrée simple)
Texture Peut être 4:3 (net) ou carrée Toujours carrée
Propriétés solid, destructible, resistance, light_emission stack_size, durability, damage, tier, multiplier
Storage storage/app/textures/ storage/app/item_textures/
Identifier check Pas de unique check Unique en BDD
❌ PIÈGE #9 : Items identifier UNIQUE
Contrairement aux blocks, les identifiants d'items DOIVENT être uniques en base de données. Tu peux avoir 2 blocks avec le même identifier (si créés rapidement), mais PAS 2 items.
❌ PIÈGE #10 : Pas de géométrie custom pour items
Les items n'ont pas de détection géométrie ou de JSON géométrie. C'est juste une image 2D dans l'inventaire. Si tu veux une forme spéciale, ce sera un block, pas un item.
❌ PIÈGE #11 : Tier + Multiplier doivent coexister
Si tu fournis un item_tier (0-10), tu DOIS aussi fournir un item_multiplier. Sans les deux, la propriété "minecraft:axe" ne sera pas générée.
❌ PIÈGE #12 : Stack size 1-64 seulement
La validation accepte 1-64. Tu ne peux pas avoir 128 items dans une stack. Max = 64 (limitation Minecraft Bedrock).

8. Questions piègues probables

# Question piègue Réponse clé
1 Comment détectes-tu la géométrie automatiquement ? Analyse du PNG : ratio 4:3 (net), transparence continue (glass), binaire (cross), sinon cube
2 Pourquoi 4:3 exactement pour net ? C'est l'unfold standard d'un cube Minecraft. Format : [top][4 sides][bottom]
3 Comment splittes-tu une net texture en 6 faces ? Calcul C = width/4, puis extract 6 régions carrées (C×C) à positions spécifiques
4 Texture 64×48 vs 64×64 : différence ? 64×48 = 4:3 (net) → 6 faces. 64×64 = carré → cube. Format détermine détection
5 Hardness = Resistance ? NON ! hardness = resistance ÷ 20. Exemple : resistance=40 → hardness=2.0
6 Pourquoi "custom:" dans l'identifier ? Minecraft namespace. Sans ça, bloc ignoré silencieusement. Built-ins = "minecraft:", customs = "custom:"
7 Identifier minuscule obligatoire ? OUI. Regex /^[a-z0-9_]+$/ strict. Pas de majuscules, pas de tirets
8 Où stockes-tu les textures ? Permanent : storage/app/textures/{identifier}_{timestamp}.png
9 Géométrie custom (JSON) obligatoire ? Non, optionnel. Si absent, la géométrie auto-détectée est utilisée
10 Glass vs Cross render method Glass = blend (semi-transparent continu). Cross = alpha_test (transparent/opaque net)
11 Texture non-carrée acceptée ? JAMAIS. Validation ratio=1 = carré obligatoire. Exception : net (4:3) détecté spécifiquement
12 Light emission : 0-15 pourquoi ? Standard Minecraft (15 = brightness max, comme glowstone)
13 Solid=false : qu'est-ce qui change ? Pas de collision/hitbox. Joueur peut passer à travers. Comme air ou fleur
14 Destructible=false : qui peut le casser ? Personne (même en mode créatif, dépend du gamemode Minecraft)
15 Max texture size 512 KB : pourquoi ? Performance Minecraft + limitation ressources serveur
16 Items : géométrie auto-détectée ? NON. Items = images carrées simples, pas de détection
17 Item identifier unique obligatoire ? OUI, unique en BDD. Blocks : non unique. Items : unique obligatoire
18 Stack size item : max value ? 64 (limitation Minecraft). Min 1
19 Tier + Multiplier obligatoires ensemble ? OUI. Si tier fourni, multiplier DOIT être fourni aussi
20 Item sans durability c'est indestructible ? OUI. Si max_durability = null, item ne se casse jamais
21 Hand equipped : à quoi ça sert ? Afficher l'item visiblement quand équippé en main (comme épée, arc)
22 Items storage vs blocks storage ? Items : storage/app/item_textures/. Blocks : storage/app/textures/

📌 Résumé

Le système de création de blocks/items repose sur 3 mécanismes clés :

  1. Validation stricte des inputs (identifier, texture, props)
  2. Détection géométrie intelligente (auto-analyse du PNG)
  3. Génération de comportement (conversion inputs → propriétés Minecraft)
✅ Points clés à retenir pour la soutenance
  • Géométrie détectée via analyse pixel (4:3, transparence)
  • Hardness = resistance ÷ 20 (pas direct)
  • Identifier DOIT avoir "custom:" prefix + regex minuscule
  • Texture stockée permanent, mais géométrie peut être custom
  • Validation stricte empêche les inputs malveillants
🚨 Pièges les plus courants
  • Net 4:3 strict — pas de ratio approximatif
  • Hardness = resistance÷20 — la formule n'est pas linéaire
  • Identifier "custom:" — obligatoire pour Minecraft
  • Texture carré — validation stricte, exception net
  • Détection auto vs custom — confusion entre les deux
